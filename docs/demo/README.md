# 2026-11-20 발표 화면: 실제 저장 예측 재생

이 화면은 **2025년 과거 평가 결과**를 재생합니다. 발표일 2026-11-20 15:00과 예측 기준시각을 구분합니다. 최신 운영용 72시간 예측은 아직 연결하지 않았습니다.

## 발표 시연 순서 (약 40초)

1. 첫 화면의 `2025-07-01 23:00 KST`와 실측 마감 `2025-06-28 23:00`을 가리킵니다.
2. “이 기준시각에서 다음 날부터 사흘간 72시간을 예측한 저장 결과입니다”라고 설명합니다.
3. SARIMAX 예측선과 실제 SMP를 비교하고, D+1 → D+2 → 전체 72시간을 선택합니다.
4. 모델을 LSTM으로 바꿔 같은 구간의 결과를 확인합니다.
5. 아래 표는 선택일이 아닌 **2025년 하반기 전체 혼합 모델 성능**이라고 설명합니다.

발표 마지막 문장: “이제 웹 화면에서 과거 평가 기간의 예측 기준시각을 선택하고, 다음 72시간의 예측 가격곡선을 실제 가격과 비교하는 과정을 시연하겠습니다.”

## 인터넷이 끊기면

`docs/downloads/smp72-offline.html`을 미리 컴퓨터에 저장하고 Chrome으로 엽니다. 모든 데이터·코드·스타일이 들어 있어 그래프 및 CSV 다운로드에는 인터넷이 필요 없습니다. 보고서 링크와 이전 화면 링크는 인터넷이 필요합니다.

## 데이터 출처 및 성능

- `smp72-2025.json`: 공통 v3 `v3_a90141b81ecd_lag72`, 발전량 보완 전 결과.
- 기존 최종 예측 CSV의 **E3 (Train+Validation 재학습 + 사전에 고정한 주간 기준선 혼합)**만 추출했습니다. 각 모델 182발행일 ×72시간 =13,104행입니다.
- SARIMAX 40%+주간60%, LSTM 50%+주간50%, LightGBM/XGBoost 각각70%+주간30%.
- 원본 CSV 해시는 JSON의 `provenance`, 원래 실험 보고서는 각 모델의 `report_url`에 기록했습니다.
- `scripts/export_smp72_demo.py --models-root /path/to/1120gradpj/models`로 재생성합니다. 학습·추론을 새로 실행하지 않습니다.
- `python3 scripts/build_smp72_offline.py`로 오프라인 파일 재생성.
- `python3 -m unittest discover -s tests/smp72_demo -v`와 `node --check docs/smp72_demo.js`로 검사합니다.
- 이미 확인한 2025년 하반기의 후속 재평가입니다. 새 독립 시험으로 표현하지 않습니다.

## 최신 2026년 예측을 연결하려면

11월20일 15시 시연에는 원칙상 **11월19일 23시 발행**, 11월20일00시~22일23시 대상 결과가 필요합니다. 발표 시각인 15시로 발행시각만 바꾸면 연구 조건이 달라집니다.

1. 서버 또는 GitHub Actions에서 최신 12그룹 입력을 수집·검증합니다. 실측 마감은 11월16일23시입니다.
2. 국내 LNG는 합의한 2026년10월 값 적용 사실을 기록합니다. 동월 단가를 사용했던 과거 평가와 조건이 다름을 표시해야 합니다.
3. 고정된 SARIMAX 모델·스케일러·특성 순서 및 주간60% 혼합을 사용하여 실제 추론합니다. 미래 달력과 중기예보는 해당 발행시각에 존재하는 값만 사용합니다.
4. 72개 대상시각, 모델/데이터 버전, 입력 가용 시각, 결측/대체율을 검증하고 공개 JSON으로 내보냅니다.
5. 키를 넣은 API를 브라우저에서 직접 호출하지 않습니다. `.env`는 공개하지 않습니다.

현재 `live-status.json`은 연결 미완료 상태만 기록하며 가격곡선을 제공하지 않습니다. 기존 `live/latest.json`의 v11/v17 파이프라인은 이 연구의 SARIMAX 혼합 모델과 다르므로 가져오지 않습니다. 2025년 결과의 날짜를 2026년으로 바꾸지 않습니다.

## 기존 화면과 배포

이전 `index.html`은 `legacy-v20.html`로 보존했습니다. 기존 JS/CSS/자동 수집 코드는 삭제하지 않았습니다. GitHub Pages는 workflow 방식입니다. `SMP72 static presentation Pages`는 main/docs 변경 시 저장된 데이터만 검사하고 정적 파일을 게시합니다. API 키·모델 실행·수집·상태 저장이 없습니다. 기존 `SMP public forecast and Pages refresh`는 별도의 과거 자동 수집 작업이며, 이 과거 재생 화면의 예측을 생성하지 않습니다. 최신 자동 수집 결과와 이 과거 재생 화면을 혼동하지 않습니다.
